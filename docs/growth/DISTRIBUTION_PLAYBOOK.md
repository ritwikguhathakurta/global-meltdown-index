# Ethical distribution playbook — Global Meltdown Index

Growth master-plan Phase 9 deliverable. This is the sustainable *system* for distribution; the
actual candidate communities already researched live against real rules/norms are in
`docs/growth/COMMUNITY_RESEARCH.md`, and the action log is `docs/growth/OUTREACH_TRACKER.md` /
`docs/growth/launch/outreach_tracker_template.csv`. This document is the policy and workflow that
governs both — read it before adding a row to either.

## The system, end to end

1. **Identify** a community or publication (see "Lead-research workflow" below) — never add a
   target speculatively just to fill a row; there must be a real, specific reason it fits.
2. **Research** its actual current rules, not a remembered reputation — see
   `docs/growth/COMMUNITY_RESEARCH.md`'s own disclosed confidence levels; most secondhand summaries
   there are explicitly flagged "re-verify before posting."
3. **Draft** content that adds real value to that specific audience, not a copy-pasted announcement
   — see `docs/growth/launch/` for channel-specific drafts.
4. **Get explicit approval** (yours) before anything goes out — this step is non-negotiable per the
   master plan's own operating rules.
5. **Post as yourself**, disclosing authorship, following that community's specific norms.
6. **Engage honestly** with whatever response comes back, including silence or removal.
7. **Log the real outcome** in the outreach tracker — not what you hoped would happen.
8. **Feed what you learned back** into `docs/growth/METRICS.md` (did referrer data confirm this
   channel worked?) and into this playbook if a norm turns out different from what was researched.

## Lead-research workflow (template fields)

For any future candidate — a newsletter, a publication, a community, a specific person — record:

| Field | What goes here |
|---|---|
| Organisation / publication | The real, named entity |
| Public contact or submission page | A real URL — never a scraped private email |
| Relevance | Why this specific audience would care about this specific project |
| Reason for outreach | What you're actually asking for (feedback, a listing, a mention) — never just "exposure" |
| Suggested content fit | Which draft in `docs/growth/launch/` fits, or what new piece is needed |
| Status | Not yet contacted / Contacted / Responded / Declined / Published |
| Follow-up date | Only if the contact's own channel suggests one is appropriate — never a generic "nudge in a week" |
| Consent / contact-policy notes | What their own submission guidelines say about how they want to be approached |

**No leads have been identified and added to this table yet.** `docs/growth/COMMUNITY_RESEARCH.md`
covers general-purpose communities (Reddit, HN, IndieHackers, etc.); specific named publications,
newsletters, or individual journalists/bloggers would need their own real research pass before
being added here — not populated speculatively in this document.

## What this system explicitly forbids

Directly from the master plan's operating rules, restated here because this is the document that
governs distribution specifically:

- Scraping private contact data.
- Bypassing a platform's own restrictions or rate limits.
- Automated mass outreach of any kind.
- Posting generic comments that just contain a link, anywhere.
- Fake accounts, sockpuppets, or a "neutral third party" framing.
- Star-for-star exchanges, purchased stars/followers, or engagement conditional on starring.
- Mass/bulk outreach to a list of people with no individual, real reason for each contact.

## Review cadence

Re-check this playbook (and re-verify `docs/growth/COMMUNITY_RESEARCH.md`'s secondhand entries)
every time a new outreach wave is planned — platform rules and community norms change, and a stale
"I checked this once" is exactly the kind of unverified claim this project doesn't allow itself to
make about its own data.
